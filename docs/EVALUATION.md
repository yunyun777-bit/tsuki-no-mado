# 推薦の評価

現在の推薦は固定係数の重み付きスコアです。ニューラルネットワークや確率推定ではありません。実利用で頻度順を上回ることは未検証です。

## ローカルで実行

```sh
npm run evaluate -- --demo
npm run evaluate -- local-data/visits.json
```

`--demo` は架空の12サイトを28日間訪問し、途中で時間帯と訪問先の対応が変わる入力を生成します。ツールの動作確認用であり、利用者に対する性能の証拠にはなりません。

実データは本人が用意した次のJSON配列を使用します。時刻はUnixミリ秒、URLはHTTP(S)です。拡張から実際の履歴を自動出力する機能は追加していません。

```json
[
  { "url": "https://example.com", "time": 1767258000000 },
  { "url": "https://example.org", "time": 1767261600000 }
]
```

`local-data/` はGitの対象外です。入力ファイルをGitHub、Issue、共有チャット等に添付しないでください。ツールはネットワーク通信せず、結果にはURLや個々の時刻を含めません。結果の件数自体を共有するかも利用者が判断してください。無効な入力を報告する際も元データを出力しません。

## 比較方法

- 訪問を時刻順に並べ、過去の訪問だけで「その時刻の次の訪問先」を予測します。予測してから訪問を学習するため、正解を先に学習しません。
- 同時刻のイベントは全件を予測した後にまとめて学習します。同一サイトの10分未満の連続訪問を除きます。
- 最初の20件を初期学習に使い、その後の訪問について上位8件への的中率（Hit@8）を比較します。
- 比較対象は、同じ保存上限・90日保持期間・候補集合を使った単純な訪問回数順です。同数ならオリジン順です。
- 未訪問のサイトも分母に含め、的中しなかったものとして扱います。`unseenSiteEvents` に件数を出します。
- 候補が8件以下の場面は順位による差が出にくいため、`eventsWithAtMostKCandidates` を併記します。
- 訪問回数の分母は `evaluatedEvents`、的中数は `hits`、割合は `hitRate` です。評価対象が0件なら割合は `null` になります。
- 時間帯は実行端末のタイムゾーンに従います。出力の `timeZone` を比較時に揃えてください。

これは過去ログを再生するオフライン評価です。「新規タブを開いた直後」の訪問かどうかは区別しません。固定サイト・手動追加・非表示や、推薦を見たことによる行動変化は再現していません。実際のUIでの使いやすさや継続利用は別途確認が必要です。

## 結果を報告するとき

データが合成か実利用か、期間、匿名の参加者数、評価件数、候補数の偏り、両方式の的中率を記載してください。パラメーター調整に使った期間とは別の後続期間で再評価します。単一の合成データの結果を「精度向上」として宣伝しません。
