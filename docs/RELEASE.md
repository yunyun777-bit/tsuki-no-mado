# 配布・公開手順

作者: yun / GitHub: yunyun777-bit / ライセンス: MIT

## ローカルの配布物

```sh
npm run check
npm run package
```

`dist/tsuki-no-mado-0.2.0-XXXXXX/` のような新しいフォルダーを作ります。既存フォルダーを上書き・削除しません。実行用10ファイル、LICENSE、PRIVACY.mdだけを含め、他のファイルが混入していないことを検査します。Chromeからこのフォルダーを読み込めます。

フォルダーの中身をZIPにすると共有できます。展開後、`manifest.json` があるフォルダーをChromeで指定します。`.git`、`local-data`、開発用ファイル、アカウント情報をZIPに含めないでください。

## 公開前

- [ ] `npm run check` が成功した。
- [ ] [Chromeの手動確認](TESTING.md) を実施し、失敗・未確認項目を記録した。
- [ ] MITライセンスと作者名を確認した。
- [ ] 公開するファイル一覧とスクリーンショットに個人情報がない。
- [ ] READMEに実装済み・未実装・未検証の境界を記載した。
- [ ] バージョンを変更する場合、manifest・package・画面と説明文の表記を揃えた。

公開直後は「試作版・テスター向け」と明記し、実Chrome検証の範囲を説明してください。GitHub Actionsは公開後にWindows/LinuxとNode.js 22/24で確認します。ローカルで成功してもCI成功とは扱いません。

## GitHub上で設定するもの

Issuesを有効にし、可能ならSecurityの非公開脆弱性報告を有効にします。CIの結果、導入方法、既知の制限を確認してからリリースを作成します。Chrome Web Storeへの提出は別の作業です。

## Codex for Open Sourceへの応募

公開URL、作者の管理者としての役割、利用実績、改善履歴、今後の保守計画が説明できる段階で応募資料を作成します。採択やPro付与を保証するものではありません。現時点で利用者数・推薦精度の実績を推定で書かないでください。
